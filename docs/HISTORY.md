# History — the stages before the first tag

This is the stage history that `CLAUDE.md` used to carry: what was built, in what order, with the dates, the issue and PR numbers, and the ADR that settled each step. The changelog starts at `v0.1.0` with no backfill (ADR-0022), so the story before the first tag lives in the ADRs and in this document.

## Stage A — the recorder (done 2026-08-13)

Spec review, then the stdlib-only CLI: `init` / `log` / `run` / `head` / `verify` / `report`. Tamper-demo tests (edit / delete / reorder / splice / regenerate, each caught) and a golden fixture pinning canonicalization. Stages A–C were implemented and merged together on 2026-08-13; SPEC v0.1 and ADR-0001/0002/0003 are `accepted`, and the format is frozen.

## Stage B — anchoring (done 2026-08-13)

`receipts anchor`: an OpenTimestamps commitment of the chain head to Bitcoin, through a minimal in-file OTS subset (ADR-0003, `docs/ANCHORING.md`). `verify --anchors` judges proofs offline.

## Stage C — the hook and explain (done 2026-08-13)

The Claude Code `PostToolUse` hook adapter (`receipts hook`, `docs/HOOK.md`), plus `receipts explain`: LLM narration of the log via an external command, default `claude -p`. The tool was still called *receipts* at this point; the rename is ADR-0010, below.

## The dogfood and Stage D — the supervisor (built 2026-08-22, closed 2026-08-31)

The dogfood closed early on 2026-08-21 (verdict: **push forward**). Stage D was grilled and ratified 2026-08-22 (ADR-0005) and **built the same day**: `supervisor.py` is a sibling stdlib-only single file driving receipts through the public CLI. Slices 1–11 merged (PRs #27, #29, #30, #28; suite at 201). It scans and serves (localhost only): recall front page with free-text search (GLOSSARY: *Recall*, testimony-labeled), status band with verdict tiers, baseline tripwire (scan exit 5), the completeness alarm over the transcript witness (flagship claim, exit 6; ratified state machine from the #15 prototype), anchor keeper with opt-in `--anchor-every` cadence, WebCrypto chain walker, and the fire-drill surface (`docs/FIRE-DRILL.md`). Security claim unchanged: *a tripwire with a memory* — detection latency only; anchors stay the only hard boundary. The hook stays outcome-blind (`.out-of-scope/001`).

The witness-calibration standing question closed 2026-08-29: the witness reads the wired PostToolUse matchers from the harness settings and skips failed tool calls (the harness fires no hook for them; the transcript marks these with `is_error` on the tool_result block, not on `toolUseResult`), so witnessed count equals receipts owed. Coverage went wide 2026-08-31 (ADR-0016, OWASP-grounded): the shipped matcher is `*` — every completed tool call owes a receipt — and calibration is effective-dated: the supervisor remembers the matchers it observes (baseline `calibration`) and judges each session by the coverage in force at its time, so matcher changes never manufacture deficits. GLOSSARY: *Coverage*. Measured envelope in `docs/HOOK.md` (~135 ms/call).

Stage D closed 2026-08-31, which also closed the release ritual: slice 12 (issue #25, the HITL readability walk + adversary pass + manual fire drill + dogfood handover) signed off, seven findings fixed tests-first (PR #63, suite 277). `docs/TOUR-SUPERVISOR.md` is the guided reading.

## Stage E — the recall surface (grilled and built 2026-08-26, ADR-0009)

The PRD is issue #40. `supervisor digest` (budget-capped, local-only session-start injection, wired by the SessionStart hook via `loxodonta.py install-hook`), `supervisor show` (one entry by entry address — an 8-hex `entry_hash` prefix, git prefix rules, re-hashed on fetch), `supervisor search` / `timeline` (the ladder past the digest window; `--all` walks the folder of repos, honoring `receipts/.unlisted`). Recall owns no verdicts: the digest cites the last scan as testimony and spawns nothing at session start. GLOSSARY: *Digest*, *Entry address*, *Unlisted*. Web front-end navigation was left as a later slice on `serve`.

## The rename and the store (2026-08-29)

The tool is named loxodonta (ADR-0010): the recorder is `loxodonta.py`, and what it writes are *receipts*. The dogfood driver retired with the rename — its installer became `loxodonta install-hook`, its status/drill duties were already the supervisor's, and `DOGFOOD.md` remains a local, gitignored, operator-side journal. The same day, the chains moved into one machine-wide store (ADR-0011, grilled in issue #47, built in PR #51; file references rebase to the project root, ADR-0012). Sessions are recorded machine-wide: `python loxodonta.py install-hook` wires the `PostToolUse` hook into `~/.claude/settings.json`, and every Claude Code session writes per-session chains into the store — `~/.loxodonta/receipts/<project-slug>/` with a `project.json` project record. Sessions run in a worktree log to the main repo's drawer, since worktrees get pruned; `supervisor adopt --root <folder>` migrates legacy layouts. `supervisor scan` (no arguments) reads every chain in the store across every repo, not just this one; `--root <repos-folder>` is the legacy per-repo layout only. Code changes still go tests-first through the public CLI.

## Stage F — harness neutrality (built 2026-09-02)

Built on `claude/agent-surface`; ADR-0019 and ADR-0020 `accepted`, restate-to-ratify passed. Prompted by the agent-first market read ("my agent uses your thing"). Read side: `supervisor mcp`, the recall surface as a **read-only** stdio MCP server — five tools one-to-one with the CLI (digest/show/search/timeline/verify), stdlib JSON-RPC, dual-era (2025-11-25 `initialize` and 2026-07-28 `_meta`), no write path by test (`docs/MCP.md`). Write side: adapters that speak the hook payload — `install-hook --codex` wires Codex CLI's PostToolUse/SessionEnd/SessionStart into `~/.codex/hooks.json` (the digest takes `--payload` there: repo from the payload's `cwd`, never read unasked because under `mcp` stdin is the wire; corrected 2026-09-03 after the Codex docs said plain-text SessionStart stdout is context); `adapters/openai_agents.py` is a stdlib-only `TracingProcessor` for the OpenAI Agents SDK (function + handoff spans, verified against `openai-agents` 0.22.0). The recorder learned two things: payload `cwd` names the project when `CLAUDE_PROJECT_DIR` is unset; `summary` is the last action-line key. Honest limits stated in the docs: coverage semantics differ per harness, the completeness witness is Claude-Code-only, the SDK adapter is in-process (one ring closer to the writer). GLOSSARY: *Adapter*. Suite 367.

## Evidence you can hand over (2026-09-08 to 2026-09-09)

Two external reviews of v0.2.0 converged on the same gap, evidence portability, and set the same test: a security engineer who has never seen the host receives the evidence, runs one command on a clean machine, gets a verdict with what each layer does and does not settle, and can state the residual trust in one sentence. Grilled 2026-09-08 into ADR-0025 and ADR-0026 (PR #185), sliced into #175 through #184, and built on `dev` across two days (PRs #186 through #195). **ADR-0025**: a remote is a head record when it is off the machine and the credentials present on the machine cannot delete or overwrite what they wrote there, so a chat webhook passes and a `gh` gist stays rejected because the token deletes; `install-hook --publish-head URL` posts head, count, session, time and event kind when a session ends, after the tail commitment and before the anchor, and the keeper covers sessions that never reached an end (`scan|serve --publish-every`). Codex got the flag once one POST was measured inside its three-second SessionEnd cap, with the wait cut to half the cap and the numbers in `docs/HOOK.md` (#183). **ADR-0026**: a session or a drawer packs into one zip carrying its chains, their anchor sidecars, the project record, a witness snapshot labelled testimony, and a plain-words README, with the harness transcript on request only because the chain names `.env` and the transcript holds what was in it; a manifest written last lists chains by head and artifacts by hash and declares its seals, so a stripped seal reads `SEAL-MISSING` rather than downgrading quietly; `--anchor` and `--sign` are both opt-in, the signature through `ssh-keygen -Y` with the recorder never touching a private key; and `loxodonta verify-package` judges the whole thing layer by layer, the recorder's own verdicts verbatim per chain, one line of residual trust, the package verdict last, exits mapped onto `verify`'s, with usage errors moved to `64` in both tools. Every slice was reviewed before it merged and every review found real defects: a shell-injectable publish URL, a DNS stall, a redirect resent as a GET, manifest path traversal, a zip bomb, empty chains passing, packaging that mutated the chains it copied, a foreign repository folded in as a worktree, a stale public key that shipped a fingerprint no signature could verify, an ssh-keygen too old for `-Y verify` reported as tampering, and six overclaims on the front door itself. `verify --ledger FILE`, the check that every published head is an entry hash inside the chain, stays unbuilt on purpose (#174, ADR-0025 ruling 4). Promoted to `main` as `v0.3.0`. Suite 532.

## The reader starts counting (2026-09-10 to 2026-09-11)

ADR-0027 `accepted` 2026-09-10, grilled against SigNoz and restated by the author. The ruling: the dashboard can count anything the chain already holds, because `.out-of-scope/001`'s subject is the **hook** — what the writer is made to record on every tool call forever — and not what the reader aggregates from fields already on the chain. The counting had arrived long before it was named: the consumption watch, the day book, and `activity_root`'s ninety-day buckets were all aggregates over the chain, built under a rule nobody had written down. An AFK bugfix loop on 2026-09-10 and 2026-09-11 then closed three lines that were teaching the operator to ignore the tool (PRs #203 through #205). **#118**: five test modules imported only under `discover -s tests`, so the single-module red/green loop a contributor runs died on `ModuleNotFoundError` before a test ran; `tests/test_suite_shape.py` now imports every module as `tests.<name>` from the repo root and holds the property. **#199**: the pending-record suppression in `check_anchors` was keyed by head *and* calendar while its comment said head, so a head settled by one calendar kept advising `anchor --upgrade` for the others, live on the author's store for 27 days across three chains; the straggler now reads `ANCHOR-UNANSWERED`, the upgrade stops re-asking a dead pool, and the scan's pending list empties through the ADR-0005 verdict-line seam with no supervisor change. **#117**: `scan --root` over a machine migrated to the store found an empty census and charged every transcript its whole witnessed count, 111 sessions reading `ENDED-DEFICIT` and the live one `ALARM-SILENT` at exit 6, while a plain `scan` of the same machine in the same minute exited 0. ## The witness learns its own edges (2026-09-11)

Two faults, both on the flagship claim, both loudest on the surface a stranger meets first.

ADR-0029 `accepted`, grilled and built the same day from issue #114. ADR-0016 ruling 2 had promised that a matcher change manufactures no scars, and there was one era its mechanism could not see: the era before the mechanism existed. `calibrate()` wrote its first observation as `{"since": null}` and `matchers_at()` handed that epoch to every earlier timestamp, so a calibration memory born after coverage went wide judged the narrow era by `*`. On the author's machine that was 133 witnessed sessions carrying 116 deficits, and roughly 95 of them were transcripts from before the hook existed at all. The ruling: the first observation stamps the moment it is made, and a session whose **first** witnessed event precedes it is `BEFORE-MEMORY` — judged not at all, evidence rather than deficit, the whole session and never half of one. The first event decides and not the last, because the last-event rule leaves the same bug alive as a live siren minutes after a stranger installs. It never takes a row: one counted block reports it on the scan, the dashboard, the export and a package's `witness.json`, with `scan --before-memory` for anyone who wants to look. The boundary stops at the epoch and goes no further, because a harness that fires no hooks and a hook an attacker killed leave identical evidence. `supervisor calibrate --since` states what was wired before the supervisor looked, may only reach time it never watched, marks what it writes as the operator's word forever, and `--forget` withdraws it. Prior art: OCSP's *unknown*, Nagios keeping `UNKNOWN` beside its failure states, Grafana rendering no-data rather than zero, git making asserted history visible, and DFIR keeping analyst annotation out of collected artifact.

Then #211, found by seeding those epochs and re-reading the store. The harness fires `PostToolUse` for a subagent's calls under the *parent* session id, so their receipts land in the parent's chain while the record of them sits in `<session>/subagents/agent-*.jsonl` — a file the witness never opened. A session that delegated read `ENDED-SURPLUS` for work it had done honestly, and what went missing with it was the ingest leg: a delegating parent spawns and writes while its subagents read and search, so the reads and greps ADR-0016 widened coverage to capture were exactly the calls a parent-only witness could not see. The largest case held 118 subagents, 534 events witnessed against 3721 receipts. The witness now reads the sidechain beside the parent, by the pairing rule already there — a sidechain result carries the `tool_result` block and not the `toolUseResult` field, and counting by the field alone found 57 of that session's 3244 sidechain calls. Every surplus in the author's store closed. Four of seven land exactly, the largest at 3721 against 3721, and the three that do not are all from before the cross-drive hook bug was fixed on 2026-08-30 — the era every other remaining deficit sits in. Cost measured rather than asserted: 20 of 171 sessions have a sidechain, about 22% more bytes per scan.

PRs #213 and #214. Suite 579. Promoted to `main` as `v0.5.0`, the release that unblocks #135: a stranger's first scan now tells the truth about the history it was not there for.

## The front door, walked by someone who had not written it (2026-09-11)

`v0.5.0` published, then the five steps of `docs/START.md` were walked against the files it actually publishes, in a sandboxed home, in the order the page asks for. The page failed, in the quietest way available.

ADR-0029 stamps the calibration inception at the supervisor's first observation, and the page's order is wire the hook, work for a week, then scan. The first observation therefore lands a week after recording begins, so every session in between falls outside the memory watching it: install, work, scan gave **0 of 3 sessions judged**, where install, scan, work, scan gave 2 of 2. A new installer following the page exactly saw nothing judged and sent an export that said nothing about completeness, which is the flagship claim and the reason issue #135 collects exports at all. Worse for a first reader than the deficit wall ADR-0029 had just removed: that one was wrong and loud, this was silent.

ADR-0030 `accepted`, restate-to-ratify passed, in the author's words: *the recorder writes down what coverage it wired, the supervisor reads it.* `install-hook` appends `{since, matchers, harness}` to `~/.loxodonta/coverage.json`, one entry per change and nothing on an unchanged wiring, written before the already-installed early return so a machine wired long ago still records what it has. `uninstall-hook` writes nothing, and the asymmetry is the argument: a start claim says more calls owe receipts, an end claim says fewer, and "nothing was owed from here" is the silence the completeness alarm exists to catch. The supervisor reads the file fresh every scan and merges it in memory, never into the baseline, so one sentence stays true of that file — it holds what the supervisor observed. A marker may fill time before the first observation and never reach past it, the rule ADR-0029 already applies to an operator's seed, and epochs now name their source so no reader mistakes testimony for observation. This narrows ADR-0005's freeze by one writer for one file in the store the recorder already owns, deliberately and in the open. Prior art: auditd, where the tool that changes coverage records the change; dpkg, whose installer keeps its own record for others to read; TLS `notBefore`, stated by the issuer because the issuer is the authority for it; and Prometheus, whose opposite convention is the one that produced the bug.

Three more faults surfaced only once the marker existed, each of them something a reader met in their first two commands. The export reported the inception from the baseline alone, understating itself by exactly the install-to-first-scan gap. The calibration words announced a matcher change nobody had performed, because a marker and the first observation describe one wiring from two sides. And the empty-store scan note told a reader to run `install-hook` when the hook was already wired, so anyone who finished step 2 and scanned out of curiosity was told to redo step 2. A fourth, found the same way and fixed before the others, was the install page showing the version line as `commit ...` when a downloaded file prints `commit unknown`, honestly, because there is no checkout to read.

Re-walked after building: install, a week of work, scan gives three of three judged, nothing before memory, and an export reading `OK, OK, OK`. The five steps work as written, with no sixth. PRs #217 and #218. Suite 590. Promoted to `main` as `v0.6.0`, the release issue #135's readers will be handed.
