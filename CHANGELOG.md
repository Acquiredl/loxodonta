# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
The log starts at `v0.1.0`; the history before the first tag lives in the
ADRs under `adrs/` and in `docs/HISTORY.md`. The tool version is decoupled
from the receipt format, which stays at `0.1` (ADR-0022).

## [Unreleased]

### Added

- `docs/TWINS.md` lists every rule written in more than one script, and `tools/twin_check.py --check` fails the suite when a copy drifts from the recorder's or a shared name goes undeclared (#337).

### Changed

- Anchor rows name their kind (`"kind": "anchor"`), and a row with none reads as an anchor. A row of an unknown kind is named by its line (`ANCHOR-UNKNOWN-KIND`), never judged, and moves no exit code (ADR-0038, #335).

### Fixed

- `supervisor scan` no longer stops with a traceback on a sidecar or transcript line holding an integer past 4,300 digits or nesting past the recursion limit. The writer can reach those files, so one line could stop the audit (#331).
- `loxodonta hook` answers a payload holding the same lines with exit 65, as for any payload it cannot read, not a traceback and exit 70 (#331).
- An anchor row missing its `head` or `proof`, or holding a field of the wrong type, is `ANCHOR-INVALID` naming the field, not a traceback. `anchor --upgrade`, the session-end anchor and `supervisor scan` skip it (#348).

## [0.9.0] - 2026-09-23

The recipient's verifier. `verifier.py` is the recorder's verify side on its own, copied from the same source, never edited by hand, and held to a set of conformance vectors that both files must pass. The verdicts were tightened where an outside review found them saying more than they knew: a relabeled format no longer hides an edit, an anchor no longer claims a block nobody checked, and exit 1 now means `BROKEN` and nothing else. Scripts that read exit codes should read the new ones. The receipt format is untouched, and its hashing is now frozen across versions.

### Added

- `verifier.py`: the recorder's `head`, `verify` and `verify-package` on their own, with nothing that writes or sends. It is copied from `loxodonta.py`, never edited by hand; CI fails a stale copy, and releases carry it (ADR-0035, #299).
- Conformance vectors in `tests/vectors/`: small chains with the verdict each must get, run against `loxodonta.py` and `verifier.py`, for a second implementation to check itself against. SPEC section 4 now pins string escaping to RFC 8785's (ADR-0035, #299).
- The receiver caps what it keeps, 1024 MiB a file and 10240 MiB in all (`--file-cap`, `--total-cap`), answering `507` past a cap and trimming nothing (#300).
- `--block-header HEX` on `verify --anchors` and `verify-package`: a Bitcoin block header from a source you trust, matched to anchors by merkle root, offline. A match names the block by its hash (#299).

### Changed

- Exit 1 now means `BROKEN` and nothing else. A missing, empty or unreadable log exits 66, an internal error 70, a held lock 75, a closed pipe 141; writers use 65, 69 and 73 too (ADR-0037, #299).
- The hashing is frozen across format versions, so `verify` walks the hashes whatever the genesis `v` claims: an edit is `BROKEN`, and `UNSUPPORTED-VERSION` (exit 4) means every hash holds (ADR-0036, #299).
- An anchor line says its attestation claims block H and the block was not checked, since a regenerated chain can carry a made-up attestation; only a matching `--block-header` makes it say the entries existed by that block (#299).

### Fixed

- The receiver gives each request its own thread and drops one not whole within 60 seconds, so a slow sender no longer holds the door (#300).
- The supervisor writes its baseline, day book and views whole or not at all, so a crash mid-write no longer leaves a baseline the next scan cannot read, and the tripwire keeps its memory of heads (#300).
- Every reader ends a line at `\n` alone, so a raw U+2028 in another writer's entry no longer reads as a false `BROKEN`; `\r\n` endings still read as the same chain (SPEC §1, #299).
- `head` and the writing verbs no longer end in a traceback on a log holding invalid UTF-8: such a tail is a damaged tail, refused, and the hook starts a sibling (#299).
- `verify` calls an entry `BROKEN` when a file reference could lead outside the project (`..`, absolute, a drive), so `--files` never hashes a file the chain chose; the recorder refuses the same spellings, `\Users\x` on Windows included (#299).
- `verify-package` refuses a zip holding two members that unpack to one file, which let a tampered chain verify `SELF-CONSISTENT`, and a manifest giving a key twice: both `UNSUPPORTED-FORMAT`, exit 4 (#299).

## [0.8.1] - 2026-09-23

Receipts that survive hostile input. Every fix here came from an outside review that tested the README's claims against the code. The receipt format is untouched.

### Fixed

- A tool call carrying a lone surrogate (`\ud800`) now leaves its receipt, recorded as escape text; before, it was lost and the chain still read `VALID` (#292).
- `verify` gives a verdict, never a traceback, on a line it cannot read: invalid UTF-8, a lone surrogate, an over-long integer, over-deep nesting (#292).
- `install-hook` and `uninstall-hook` touch only the hook entries they wrote, keep the first backup, write atomically and write through a symlinked settings file (#293).
- The supervisor reads a user's own hooks as theirs too, so after `uninstall-hook` a hook named like `upload_receipts.py` no longer reads as the recorder (#303).
- On Windows, `digest`, `show`, `search`, `timeline` and `report` no longer crash on a receipt holding an emoji or CJK character; all three tools write UTF-8 (#294).
- Recall prints receipt text as data: control, bidi, zero-width and tag characters become visible escapes, and the digest and MCP say the text is never instructions (#295).
- A receipt field named to forge a `VALID` line no longer fools the supervisor's reading of `verify` (#295).
- `run` leaves its receipt when interrupted, when signalled by its own command, and when the command cannot start, keeping the command's exit status; a signal ignored at start stays ignored (#296).
- The README's `drill` line runs as printed (#297).

### Added

- `python tools/house_check.py --front-door`: the first screen, orphan images, doc and ADR indexes, root files and CHANGELOG bullet length, now gated in CI (#298).
- `docs/README.md` and `adrs/README.md`, an index for each folder.

### Changed

- The README's first screen says what it is, who it is for and how to install, shows the demo GIF, and answers "Why not just…".
- `GLOSSARY.md` moves to `docs/GLOSSARY.md`; `lychee.toml` moves to `.github/`.

## [0.8.0] - 2026-09-22

The release that carries two arcs and a change of direction. The profiles arc gave the installer one word for what leaves the machine, and gave the entries themselves somewhere to go: `receiver.py`, the third single file, the far end of a URL that can only add. A bugfix round then wired the failed-call event, made a headless `serve` keep its keepers turning, and drew the topology on one page. The direction grill that closed the cycle ruled who the design answers to first, the person handed a package who must decide alone whether to believe it, and wrote down where the project is going, the published work it stands on, and what it can and cannot claim. Four fixes came out of testing an outside review's claims rather than taking them: a verifier that no longer says `VALID` of a line that is not an entry, a forked chain that ends the way a torn one does, an append that reaches the disk before it is reported, and a setting that no longer stops every verb. The receipt format is untouched.

### Added

- `supervisor serve` answers `GET /metrics` in the Prometheus text exposition format, so the Prometheus, Grafana, Elastic or pager an operator already runs becomes the siren for a tripwire that until now only shouted on a page somebody had to be looking at (#252, ADR-0033). Gauges only, fifteen families: chains by verdict, sessions by completeness state and by dormancy tier, sessions running hot, heads no anchor covers yet, heads with no row in the publish memo beside them, publishing wired with nothing sent, the last session-end step that failed per step, the scan's exit code and its age in seconds, and the tally. Every name starts with `loxodonta_` and says the mechanism it counts rather than the conclusion a reader might draw, and every help line ends with `(verdict)`, `(witness verdict)` or `(testimony)`, so a scrape says which numbers came from `verify`, which the supervisor decided from its own watching, and which count writer-stamped lines. The body is one pure function over the scan report the server already holds, so a scrape starts no second walk of the store and no number can disagree with `scan --json`. Pull only: nothing is pushed to any vendor, no credential for a monitoring service sits on the machine, and the route takes the loopback bind and the `Host` refusal the dashboard has, which makes reaching it from another box the operator's tunnel or reverse proxy. The names are frozen from the release that carries them; a state the scan grows later is a new label value and a line in `docs/METRICS.md`, never a renamed metric.
- `install-hook --profile full --remote URL`, the strongest tier and the one that sends the entries themselves (#249, ADR-0031 ruling 1). One word wires the session-end anchor, the published head and the published chain, and all three go to the one URL named once, because the far end tells a head from a batch of entries by content type. What the tier claims is one sentence and no more: head and receipts go to a remote you name, and a wiped log survives there as of the last send. What it costs is said before the settings file is touched, on both harnesses and once per install: every entry leaves, with its timestamp, actor, action line and file references, and action lines are command lines that can carry anything the agent typed; and once `serve` publishes, every chain already in the store goes too, each from its first entry. `--profile full` without `--remote` is a usage error, exit 64, that writes nothing and prints the two ways to have a remote: the receiver on a second machine, or any URL that appends and refuses delete; `--remote` beside another profile is refused the same way. The flagless ladder gains its third rung, and the coverage marker's epoch gains `remote` beside `profile`: the one URL at `full`, and under `custom` the chain's when one was given and the head's otherwise. `supervisor serve` follows it: with a `full` marker and no publish flags the keeper sends both routes on the same six-hour default the anchor keeper runs on, the head first and the chain after it, on the clock `serve` keeps for both keepers with nothing polling it (#271), the six hours being the ripeness test each turn applies rather than a timer, and the startup line names the routes, the cadence and the install that set it; a URL typed at `serve` replaces the target for both routes, `--publish-every` typed alone at `full` keeps the marker's remote, and `serve` holds that remote to the installer's own rule before sending anything there. The keeper follows a harness's profile only while that harness's recorder is still wired, so after `uninstall-hook` and a restart it stands down and the startup line says `no recorder wired`, while the marker, as ADR-0030 rules, is never written to on the way out. On Codex the tier records itself and wires both publishes, the session-end anchor stays refused (ADR-0024), and the notice says who anchors instead. Every quick step of a Codex session end now shares one window of half the cap, the head, then the chain, then the stamp, each POST waiting its own bound or what is left of the window, so a remote that is down no longer holds the hook past Codex's three seconds, where Codex stopped it before the step could write its attempt row (#262). Measured with a 2 MB transcript, two silent remotes went from 3.27 s to 1.73 s and three from 4.75 s to 1.73 s, and a step the window closed on says so in its row. Claude Code's budgets are unchanged, since its twenty-second hook already held the worst case. `uninstall-hook` takes the wired command and every flag on it, and `drill` goes on sending nothing anywhere while naming the tier it found.
- `install-hook` takes a profile, one word for what leaves the machine (#246, ADR-0031). `--profile local` is the flagless install and wires nothing that leaves; `--profile timestamped` is `--anchor-at-session-end` under the beginner's word, a 32-byte digest of the chain head at each session end; `--profile custom` is the raw flags as before, and the raw flags typed with no profile are the same thing. A raw flag beside `local` or `timestamped` is refused, exit 64, naming `custom`, `--authority` beside `timestamped` excepted (below); `full` lands with the published chain, above, under the same rule. The flagless install prints the ladder in place of the tier line #221 added: the profile it left you on, then one row per tier, the row above naming the flag that reaches it. The coverage marker's epoch gains `profile` beside the matchers, a re-run with the same choice appends nothing, and `supervisor serve` follows the strongest tier any harness declares: a `timestamped` marker runs the anchor keeper every six hours with no flag typed, an explicit `--anchor-every` still wins, and the startup line says which cadence is in force and where it came from. Both keeper cadences turn on a clock `serve` keeps itself: with one in force it takes a fresh reading of the store a minute after the last reading finished, so a `serve` run as a background service with nobody watching the page keeps its cadences, which is the case the keeper exists for (#271). On Codex, `--profile timestamped` records the tier and wires no anchor, since its session-end anchor stays refused (ADR-0024), and the supervisor anchors on its cadence.
- `receiver.py`, the third single file: the far end of the published chain and the published head, run on a machine the writer cannot reach (#247, ADR-0031). It mints one URL on first start, prints the same one on every start after, and retires it on `--new-token`. It answers only a POST at that path: a JSON head is appended to `heads.jsonl`, an NDJSON chain batch to the file the `X-Loxodonta-Chain` header names, and a header that is not a receipt file name is refused with nothing written. An exact duplicate line is dropped, a line with a known `n` and a different hash is kept beside the original, and the 200 comes only after the bytes are on disk. There is no route that returns, lists or deletes, which is what makes the URL a head record: a credential that can add and cannot take away. `--cert` and `--key` speak TLS through the stdlib; without them the startup line says plain HTTP. It never runs `verify`; the recorder's `verify --log` on its chain file is the acceptance test, `VALID` after honest batches and `BROKEN` at the first entry a regenerated chain replaced. The wire contract is `docs/RECEIVER.md`, and `--version` moves with the other two files.
- Every session-end step writes down how it went, and the scan reports it (#240; #245, slice one of PRD #244). After the anchor and the head publish, the hook appends one row of kind `attempt` to the sidecar that step already owns, carrying the step, the time, the budget and the outcome, never the URL. Readers that judge (`verify --anchors`, the keeper, `verify-package`) skip the row by its kind. `scan --json` and the dashboard's project tile gain, per chain, when a head last left by any route and the last failed attempt, whether or not a keeper cadence is set, and the scan says in one sentence when publishing is wired on the SessionEnd command and no chain holds a sent head. The chain's schema and the SPEC are untouched. A verifier or supervisor from before this change reads an attempt row as an invalid anchor record or as a departure, so a package recipient needs this release or later.
- The chain head can be stamped by a timestamp authority the operator names, beside the anchor and never instead of it (#250, ADR-0032). `loxodonta stamp --authority URL` encodes an RFC 3161 request by hand (version 1, a SHA-256 imprint of the head, a nonce, `certReq` true), posts it as `application/timestamp-query`, reads only whether the authority granted it, and keeps the whole response verbatim, base64, in a third sidecar, `<log>.stamps.jsonl`, beside the head, that head's `n`, the time asked and the authority's URL, which is written down because it is not a credential. The token itself is never parsed. A head that already holds a token is not asked about again by either door, so a cadence cannot collect tokens for one unchanged head, and a token the authority granted that this machine could not write down is recorded as that and never as granted. `--authority-chain` without `--stamps` is a usage error, exit 64, since a run that ignored it would answer `VALID` with nothing judged. `install-hook --profile custom --authority URL` wires the same query into every session end, after the published head and before the anchor so the slow calendar cannot cost either fast POST, under the same budget, quiet and best-effort, with the attempt row #245 landed saying how it went under the step `stamp`. `verify --stamps --authority-chain FILE` judges each token offline through `openssl ts -verify` against the recorded head's digest: a token openssl rejects, or a row whose head is nowhere in the chain, is `STAMP-INVALID` and exit 3, beside `ANCHOR-INVALID`; with no `openssl` on the path, or no chain file given, the token is `stamp not judged:` with the reason, a note and never a verdict, and the exit code stays the chain's, which is the posture ADR-0026 set for `ssh-keygen` and the same stdlib wall. One rejection is the calendar's and not the token's (#264): openssl checks the authority's certificate as of the moment it verifies, so a genuine token fails once that certificate expires. When expiry is openssl's reason, `verify` asks again as of the time the token states, its own signed time as `openssl ts -reply -token_out -text` prints it and never the unsigned status text around it. A token that holds then is `stamp not judged: the authority's certificate expired after the token was issued`, and one that fails then too, or states no single time that can be read, is `STAMP-INVALID`. That covers a tampered one: openssl checks the certificate before the signature, so only the second check sees the tampering. An `openssl` without `-attime` says so as a note, and long-term validation is not built. `verify` still never fetches. What the authority adds over the anchor is speed, one round trip rather than hours, and standing, the qualified kind of timestamp being recognized evidence where a block header formally is not; what it costs is the difference in kind, a token being somebody's signed word where an anchor's proof is nobody's product. So the sidecar, the verb, the verdict and every message say stamp and never anchor, and no authority is baked in: whom to trust is the whole choice. The profiles, the keeper's cadence, the package's verdict line and Codex's own cap are the entry below.
- The published chain: the entries themselves leave the machine, to a remote that can only add (#248, ADR-0031 rulings 2 and 3). `publish --chain --log LOG URL` sends the chain's lines exactly as they sit on disk, newline-delimited under `application/x-ndjson`, with the chain's file name, the session, the `n` range and the head in headers named for the tool: from genesis the first time, from the entry after the last acknowledged one every time after, in batches under the receiver's cap. `install-hook --profile custom --publish-chain URL` wires that send onto the SessionEnd command by its raw flag, and `--profile full --remote URL` in one word, after the head and before the anchor, under the head's budget, and the installer says what leaves before it writes anything, because action lines are command lines. The memo beside the chain gains one row of kind `chain` per acknowledged batch, written on a 2xx and on nothing else, never carrying the URL; a send that was refused, timed out or cut off leaves the `attempt` row #245 defined and no chain row, so the next send resumes from the same cursor and the receiver drops what it already holds. `supervisor scan|serve --publish-every AGE --publish-chain URL` sends on the keeper's turn, after the head, through that same command, the scan's sentence about publishing wired in name only now reads each route on its own, and `left` names the door something last left by: `published-chain` beside `published` and `anchored`. Codex gets the flag too, taking what the head leaves of the half of its three-second cap the quick steps share (#262, above): the batches that fit go and the rest waits at the cursor. The receiver's file verifies `VALID` with `verify --log` once the session has ended. A supervisor from before this change reads a chain row as a published head, so an old `serve` left running beside this recorder stands its head keeper down once a batch lands and stops posting the head: upgrade the two files together.
- The authority timestamp reaches the profiles, the keeper and the package (#251, ADR-0032 rulings 2, 3 and 4). `install-hook --profile timestamped --authority URL` and `--profile full --remote URL --authority URL` are accepted: the authority is the one raw flag a tier takes beside its own, because a tier can name the mechanism and never the authority, and beside `--profile local`, where nothing leaves at all, it is refused like any other. The marker's epoch records the authority beside the profile, and `supervisor serve` reads it: when an authority is named, the anchor keeper's turn stamps the same ripe head it anchors, on the anchor cadence and never a second one, skipping a head that already holds a token, and the startup line says so on the anchor's clause, only when that clause has a cadence to ride, naming the harness whose install named the authority. That authority is the one the newest epoch names among each harness's newest that name one, so an install for another harness without the flag never withdraws it; like the profile, it is followed only while the recorder of the harness that named it is still wired, and one the marker names that is not a plain http or https URL stamps nothing, the startup line saying why in either case. `supervisor package --stamp URL` seals a package the way `--anchor` does, through a new `loxodonta stamp --manifest PATH` that stamps a file's sha256 and writes `manifest.json.stamps.jsonl`; the manifest declares the seal before the token exists, so a stripped token is `SEAL-MISSING` and never a quiet downgrade, and the package now also carries each chain's own stamps sidecar, which until now stayed behind while the anchors sidecar travelled. `loxodonta verify-package --authority-chain FILE` judges every packaged token exactly as `verify --stamps` does and prints `+ STAMPED` beside `+ ANCHORED` when the manifest's token holds, never in its place: a token is its signer's word about a moment, so with no anchor the verdict's limit still names a wholesale regeneration. A manifest token its certificate outlived earns no rung and fails no seal: its seal line says it was not judged and why, and so do the residual trust and the verdict when it is the only token over the manifest, and one that fails as of its own time too is `SEAL-INVALID` (#264). What the rung says is what openssl checked, that a key the recipient's chain file certifies signed the manifest's sha256, and never who: the name in the stamps record is the packer's note in a file the manifest does not list, printed as testimony. One chain file judges every token in the package, so a package stamped by two authorities is judged with one chain file holding every authority's certificates (concatenated PEM). A chain's tokens are judged only when the manifest lists its stamps sidecar, so a package from before stamps travelled verifies exactly as it did. A chain's bad token inside a package is named `STAMP-INVALID` rather than borrowing the anchor's word, since an authority timestamp is never called an anchor. Codex gets `--authority` too, the stamp last in the session end's shared window (#262), taking what the two publishes leave: its one POST was measured inside the cap the way #183 measured the head, costing 0.07s over the seal, and a silent authority ends the hook at 1.67s worst, where the default three-second wait held it to 3.19s, past the cap; the numbers are in `docs/HOOK.md`. One thing the same slice brought in line: `publish` and `publish --chain` now write the attempt row of #245 when their own query fails, as `stamp` already did, because those three verbs are what the supervisor's keeper runs on its cadence. A failure on the keeper's turn was readable for one tick of one scan and then gone, and `last_failed` and the metric beside it answered for the session-end half alone.
- A new remote receives each chain from its genesis (#263). The publish memo's chain rows now say which remote took them, as `remote_id`, the first 16 hex characters of the SHA-256 of the URL and never the URL itself, and the chain's cursor is per remote. Pointing the chain elsewhere, by re-running `install-hook --profile full --remote` with a new URL, a changed `--publish-chain`, a keeper told another URL or two harnesses naming two remotes, used to resume from the old remote's cursor, so the new receiver's file started mid-chain and could never verify. Now a remote that has taken nothing gets each chain from entry 0, its file verifies `VALID`, and a remote sent to before resumes where it stopped. A chain row written before this change names no remote and counts for none, so after the upgrade each chain goes once more from genesis, and a receiver that already holds it keeps its file unchanged. The keeper reads the cursor the same way, and the sentence about publishing wired in name only counts the chain route as sent only to the remote the SessionEnd command names. Heads are unchanged: a head is posted once, wherever it went. A recorder from before this change takes the largest `last` across all remotes, so upgrade `loxodonta.py` and `supervisor.py` together.
- `docs/TOPOLOGY.md`, one page that draws where each piece runs and what its evidence is worth there (#223). A reader arriving cold had to assemble that picture from four documents. The page draws it once: the agent's machine, where the recorder, the store and the supervisor all sit within the writer's reach, so the scan and the dashboard are fast detection and never proof; what leaves it on its own at each profile; the calendars and a timestamp authority; the receiver's machine, where `verify --log` on the published chain, and every published head checked at its own `n`, are worth something about regeneration; and the recipient of a package. It says as plainly what does not exist: nothing gathers chains or packages from several machines into one reading, and `verify --ledger` is not built (#174). The README links to it in one sentence after the supervisor's commands, and `docs/RECEIVER.md` and `docs/PACKAGE.md` in one line each. `docs/RECEIVER.md` §8 also stops saying the keeper's cadence bounds the unsent tail: the keeper sends nothing until the head has sat unchanged past its cadence, so a busy session's tail waits for its session end. And §6 stops reading the first version of a chain to reach the receiver as the original: the writer holds the URL too, so the order says only which arrived first, and the published heads checked at their `n` tell which one was regenerated.
- `supervisor scan` says how long the harness keeps session transcripts (#260). Claude Code deletes a transcript once it is older than `cleanupPeriodDays` days, 30 when the setting is absent, and from harness v2.1.248 keeps one started or last continued in Claude Desktop or Cowork at any age unless `desktopSessionCleanupPeriodDays` sets a limit. The scan reads the setting from the user settings file beside the witness, the one it already reads for the wired hook, and `scan --json` gains `completeness.transcript_retention`: the days, whether the setting is there, its value as the file holds it, the file, and one line of words, which the dashboard's evidence tab shows beside the witness's other lines. Not set reads as the harness default of 30; a value that is not a whole number of days, 1 or more, is repeated as it stands, no number is read from it, and the line says the harness pauses its sweep then unless managed settings set one; no settings file adds nothing. Every line says which settings it did not read. The wordmark, tagline and badges stay, and so do the three pinned command blocks the suite runs. What the front door no longer says, it links to.

The README and `docs/START.md` show the ladder the installer prints, at the step that wires the hook, and the README says three things it did not: at `full` a wiped log survives at your remote as of the last send, the authority timestamp is the addition for operators who need seconds or standing, and the supervisor works with Grafana and Elastic through Prometheus. Both pages also say which doors check for a regular file: the hook does, and `log --file`, `run --file` and `verify --files` do not. The recorder is unchanged and no hash moves.
- The house checker learns the tool's old name, the words that must not stand in for five GLOSSARY terms and for the raw archive the *Package* entry names, and the code (#241). The old name fails where it can only be the tool: the old command written as code (`receipts verify` in an inline code span or on a line of a fenced block), the old script run as a command (`python receipts.py verify`), and the tool named as one after "the" or "a" ("the receipts CLI", "a receipts tool", and the same with command or recorder). Bare prose is not judged, because before a verb the word is the plural noun as often as the tool, and the history, the changelog, the two tours and ADR-0001 to ADR-0009, which ADR-0010 left as they were written, keep the old name. A synonym table beside the anti-terms carries each term, the words refused for it and the GLOSSARY's reason: *profile* (not a "protection level", "full security" or a "full mode"), *published chain* (not a "chain backup", nor the chain's "mirror" or "replica"), *receiver* (not a "chain server", nor a "collector" for the entries), *package* (not "a bundle"), the *raw archive* (not a "raw bundle"), and the *authority timestamp* (never a "TSA anchor"). Each pattern ties a noun to what it would stand for, so "backs up the settings file", "back up your receipts", "the report mirrors the chain", "the legacy mode", "OpenSSL's security level" and "an MCP server" pass, and a bare noun such as "the server" is not judged; a synonym warns everywhere and fails on the front door. The anti-terms and the synonym table now also read `loxodonta.py`, `supervisor.py`, `receiver.py` and the adapters, identifiers, strings, comments and docstrings, with an underscore read as a space. Only a comment or a docstring can refuse a word there, a file that does not tokenize refuses nothing, and a synonym there fails rather than warns. Every rule's refusal got narrower on the way: a refusing word no longer reaches across the end of a sentence, "whether or not" refuses nothing, and an ADR's rejected alternative refuses only the words inside its bold heading. What the new rules caught is reworded: the command in SPEC §7 and §8, the two out-of-scope records, the fire drill and the CLI tests' docstrings now say `loxodonta`, and the "bundle" that stood for a profile or a package in the GLOSSARY, the recorder's docstring, ADR-0007's list of what carries the manifest hash and ADR-0031's prior art says what it meant. ADR-0031's rejected alternative, whose bold heading calls the profile a "bundle", stands as written and passes as a rejected alternative. The GLOSSARY's *Published chain* and *Receiver* entries now name the words they refuse, as *Package* and *Profile* already did.

### Fixed

- A tool call that fails now leaves a receipt on Claude Code (#239). The harness sends `PostToolUse` only for a call that completed; a call that ran and failed fires `PostToolUseFailure`, which the installer did not wire, so on the author's machine about one covered call in thirty, the failing ones, left no receipt, and those are often the calls a forensic reading wants. `install-hook` now wires it beside `PostToolUse`, with the same command on the same matcher, and `uninstall-hook` takes it out with the rest. The recorder reads the fields it reads for any call, so the receipt records the action attempted and never whether it worked, and neither the chain's schema nor the SPEC moves. A denied call, one the harness rejects before it runs, and a running call that is cancelled still fire nothing. The witness moves with the wiring, ruled in ADR-0034: a failed command whose result opens `Exit code N`, which says it ran, is owed a receipt from the install that wired the failure event; a rejected input, a marked denial, or a shell failure without that line owes nothing; and any other tool's failure, whose words cannot tell a tool that started from a call that was blocked, is counted as `may_owe`. The calibration and the coverage marker carry the event's matchers as `failures`, so a failed call under an install that never wired it is judged exactly as before. Receipts are now paired with calls tool by tool rather than as two totals, for every install, and within a tool they go to its `may_owe` calls first, so a receipt a failed call may have left can never pay for one an owed call lost, in its own tool or another. The price, taken over a mask on a starved call: a non-shell call a `PreToolUse` hook blocked fired nothing, and in a session that used that tool otherwise it reads as a deficit, live while the session runs. Where a session is short in one tool and over in another, the deficit is what it reads, and the deficit words now say a tool's receipts fall short of the calls the witness saw it make. A line written by hand that names no tool the session used keeps the old pooled reading. A package's `witness.json` carries `may_owe` beside the counts. Codex is unchanged, since its `PostToolUse` already fires after a command that exits non-zero. An install from before this change records no failed call until `install-hook` is run again, and the scan's recorder line says so until it is.
- `supervisor serve` never turned its keepers unless something asked it a question (#271). Both keepers run inside the scan, and `serve` scanned only when a request for `/api/status` or `/metrics` arrived, so a `serve` started as a background service with no page open and no scrape pointed at it anchored nothing and published nothing, for as long as it ran. Measured against v0.7.0: `serve --anchor-every 0s` pointed at a fake calendar and left alone for a minute submitted no digest at all, where the same command on this release submits one within a second. The session that never reached its end is the one the keeper exists to cover (ADR-0025), and it is the session an attacker would pick. With a cadence in force, by flag or by profile, `serve` now runs a daemon thread that takes a fresh reading of the store a minute after the last reading finished, through the same door and the same lock a request goes through, promptly at start rather than a minute in, and stopping with the server. With no cadence in force nothing starts and nothing changes. A reading that cannot finish at all says so in one line on stderr, naming the kind of failure and not repeating it on every turn. Two things the clock made visible rather than caused: the startup line's `anchor off` now adds that pending proofs are still upgraded on each turn, a request to a calendar the line did not mention before, and the keeper's own turns stay out of the day book, since a machine asking itself every minute is not somebody looking at the page (ADR-0014).
- A `LOXODONTA_CHAIN_BATCH_BYTES` that was not a number stopped every verb, `--version` and `verify` included, with a traceback at import. The knob is the test suite's handle on the publish path and is now read there, when a send needs it, and a value that is not a positive number is the default, the way `LOXODONTA_LOCK_TIMEOUT` already behaves.
- `verify` said `VALID` of a line that was not an entry: a key given twice (a last-wins parser hashes it clean while a first-wins parser reads another action), or a field of the wrong type with the hash recomputed over it (`files` as a string, `n` as `true` or `1.0`, `action` as `null`). Some of those crashed a reader instead: `verify --files` and `log --file` on a `files` that was not a list, plain `verify` on a `ts` that was not a string. SPEC section 6 step 1 now asks for each field once and of its section 2 type, and the walk refuses a line that fails it by name (`BROKEN at entry N: key 'action' given twice`, `BROKEN at entry N: files is not an array`) and carries it as nothing, so no reader touches it. Verifier behavior, not a format change: every chain in the author's store, 80 of them, gives the same verdict and exit as before.
- A lock taken from a writer paused past the staleness window left two entries claiming one `n`, and because that tail still parsed, no sibling chain started: every later receipt was laid over the fork until an innocent race read as tampering in the middle of the file (found by test on 2026-09-20; ADR-0004 addendum). A chain whose final entry's `n` is not its line number is now damaged the way a torn tail is: the hook starts a sibling, and `log`, `run`, `head`, `anchor`, `stamp` and `publish` refuse. The forked chain is left as it lies, and `verify` names it `BROKEN` as before.
- `logged entry N` could be printed while the entry still sat in the operating system's cache, and the receiver already synced before answering. Every chain write, the genesis included, is now pushed to the disk before it is reported, inside the lock: about 2 ms where the store lives, against about 135 ms for a hook call. A crash that lost a written receipt read at the witness exactly as a killed hook does, and an innocent loss should not wear that face. If the sync itself fails the entry is still written and a warning says so. SPEC section 1 states the rule and what remains outside it.

## [0.5.0] - 2026-09-11

The release where the witness stops claiming more than it saw, and starts seeing all of what it should. ### Added

What such a session owed is unknown, so it is judged not at all: evidence, not deficit, and no receipt of its is called missing. It never takes a row. One counted block reports it on the scan, on the dashboard beside the calibration note, in the field-data export and in a package's `witness.json`, because a store older than its supervisor holds scores of these and a listing they fill is one where the sessions that mean something cannot be found. `supervisor scan --before-memory` lists them for anyone who wants to look.

It inserts an epoch only ahead of the first observed one and refuses anything later with no `--force` behind it, because observed time is the one part of the calibration memory that is not testimony. A seeded epoch is marked as the operator's word permanently, every surface that judged by one says so, and `--forget <ts>` withdraws a statement without hand-editing a writer-reachable file. `--root` mirrors `scan`'s.
- `docs/START.md`, the page for someone who has already decided to run the tool: five steps from the releases page to `supervisor export`, with the agent install offered above them as a copy-pasteable prompt for the Claude Code or Codex the reader most likely already has in their terminal, and the plain statement of what it means to ask an agent to wire up its own recorder. ### Fixed

- The completeness witness read only a session's parent transcript, so every tool call a subagent made counted as an unowed receipt (#211). The harness fires `PostToolUse` for a subagent's calls under the *parent* session id, so their receipts land in the parent's chain while the record of them sits in `<session>/subagents/agent-*.jsonl`. A session that delegated therefore read `ENDED-SURPLUS` for work it did honestly, and the ingest leg ADR-0016 widened coverage to capture went missing from the completeness picture altogether, because a delegating parent spawns and writes while its subagents read and search. `witness_files` now reads the sidechain beside the parent. The pairing rule is the one already there: a sidechain result carries the `tool_result` block and not the `toolUseResult` field, so keying on the field alone found 57 of one session's 3244 sidechain calls, and the two shapes agree wherever both appear across every transcript in the author's store. Every surplus in that store closed; four of the seven land exactly, the largest at 3721 against 3721, and the three that do not are all from before the cross-drive hook bug was fixed on 2026-08-30.
- The witness judged sessions from before its own memory by today's matcher (issue #114). `calibrate()` wrote its first observation as `{"since": null}` and `matchers_at()` gave that epoch to every earlier timestamp, so on a machine whose calibration memory began after coverage went wide every session recorded under the narrow matcher was re-judged by `*`. ADR-0016 ruling 2 promised a matcher change would manufacture no scars; this was the one case its mechanism could not see, because the change predated the memory. The first observation now stamps the moment it is made, and a store carrying the old `null` has it stamped on the next scan. ## [0.3.0] - 2026-09-09

The release that makes the evidence portable: a session or a drawer packs into one file, and one command on a machine that has never seen yours judges it layer by layer and says what each layer does not settle. Chain heads can leave the machine as a session ends, to a remote the credentials here cannot delete from.

### Added

- `supervisor package <session-id | entry-address>` (ADR-0026, #176): one session as a package, siblings included: every chain and its anchor sidecar, the drawer's project record, `witness.json` (the completeness row and the scan's verdicts, labelled testimony in the file), a plain-words README, and `manifest.json` written last, format `loxodonta-package/1`, chains listed by head and entry count, every other file by sha256 and byte count, `"seals": []` declared. A zip by default, `--folder` for an unpacked folder. `--anchor` and `--sign` are later slices.
- `supervisor package --repo PATH`, and the current repository's drawer when no selector is given (ADR-0026 ruling 1, #178): the second unit, a whole drawer, every session and every sibling, resolved the way `digest --repo` resolves a repository (`CLAUDE_PROJECT_DIR`, else the current directory) and including the drawers of its harness worktrees (ADR-0023). The manifest's unit is `{"kind": "drawer", "project": ..., "sessions": N}`; `witness.json` names its unit and carries one completeness row per session, a list for both units; the README says how many sessions and chains travel and lists chains by session. A session whose chains sit in more than one drawer refuses the whole drawer package, naming the session, so half a session never ships quietly. A selector and `--repo` together exit 64. Store-wide packaging stays `export --raw`'s job. The drawer package is named for the drawer folder, the slug, which is safe on every filesystem and never collides; a repository of its own checked out under .claude/worktrees/ is not packaged as a worktree.
- `loxodonta verify-package PATH` (ADR-0026): judges a zip or a folder layer by layer, the recorder's own `verify --anchors` output verbatim per chain, each artifact against the manifest, then the package verdict with its stated limit and one line of residual trust. Exits map onto `verify`'s: 0 `SELF-CONSISTENT`, 1 `CHAIN-BROKEN`, 2 `ARTIFACT-DIVERGED`, 4 `UNSUPPORTED-FORMAT` (a refusal); gravest wins. Chains are judged by walking, never by file hash, so a Windows unzip that changes line endings still verifies. `docs/PACKAGE.md` has the format and the ladder. A package is refused, never judged, when it could not be read safely: every manifest path must be a bare file name, a zip declaring more than a gigabyte unpacked or damaged past its end record is refused unopened, and a manifest whose shape is off is refused unread. The verdict is the last line.
- `supervisor package --transcript` (ADR-0026 ruling 2, #179): the harness transcript ships on request only, because the chain holds `Read: .env` with a fingerprint and the transcript holds the contents of `.env`, so packaging it can hand the recipient the very secret a session exfiltrated. With the flag, each packaged session's transcript, the one the completeness watch paired with it, travels while it is still on disk as `transcript-<session>.jsonl`, listed by sha256 and byte count like any post-close artifact and named on the session's chain listings (`"transcript"`, siblings sharing it); the README says, per session, whether it is present and if not why: not requested, or no longer on the packing machine. `verify-package` judges every transcript commitment in a chain against the packaged transcript the way `verify --transcript` does, the recorder's lines verbatim: `TRANSCRIPT-DIVERGED`, exit 5, when a committed prefix differs, outranking `ARTIFACT-DIVERGED`; when the chain holds commitments and no transcript travelled, `TRANSCRIPT-UNRESOLVED` and no verdict. A chain listing naming a transcript that is not a bare file name, or that the artifacts do not list, is refused. `verify --transcript` itself now states the tail after the last commitment in bytes, the window the chain never vouched for.
- `supervisor package --anchor [--calendar URL]...` (ADR-0026 rulings 4, 6 and 7, #180): the package's first seal. After the manifest is written, declaring `"seals": ["anchor"]`, its sha256 goes to the OpenTimestamps calendars once through the recorder's new `loxodonta anchor --manifest PATH`, and the proof ships beside it as `manifest.json.anchors.jsonl`, an ordinary anchor record whose `head` is the manifest's digest and which has no `n`; in the zip it is the member after the manifest. `loxodonta verify-package` judges the manifest anchor offline the way `verify --anchors` judges a chain's: a completed proof prints its block height and merkle root for the recipient to confirm and earns `SELF-CONSISTENT + ANCHORED` on the verdict line, with a residual-trust line that says the package existed by that block; a pending proof leaves the rung unearned with a note, and `loxodonta anchor --upgrade --manifest PATH` completes it later; a declared anchor with no sidecar is `SEAL-MISSING`, and a record for another digest, or one whose proof does not replay, is `SEAL-INVALID`, both exit 3. Chain anchors from session end stay detail under each chain and never earn the package rung. What leaves the machine is the manifest's 32-byte digest, to the public calendars, only with the flag; without it the manifest declares `[]` and nothing is posted; a calendar that accepts nothing leaves no package behind.
- `supervisor package --sign KEYFILE` (ADR-0026 rulings 4, 6 and 8, applying ADR-0008; #181): the package's second seal, the issuer signature, alone or with `--anchor`. After the manifest is written, and before the anchor when both are asked for, so a signing that fails costs no calendar submission, the supervisor has `ssh-keygen -Y sign -n loxodonta-package` sign the manifest's shipped bytes with the SSH private key at KEYFILE and ships `manifest.json.sig` beside it with `manifest.json.pub`, the public key, which is testimony: `KEYFILE.pub` when it exists, else what `ssh-keygen -y` derives, its two tokens only, since the comment is a name. Neither tool reads the private key; only ssh-keygen is run with it, and its own prompts, a passphrase or a hardware touch, reach the terminal. The manifest declares `"signature"` in `seals`, after `"anchor"` when both; in the zip the signature, the key, and the sidecar follow the manifest in that order. Before anything is written the supervisor verifies the signature under the key that ships, so a stale `KEYFILE.pub` is refused at packaging instead of shipped; a `~` in KEYFILE means home on every shell. A signing that fails leaves no package behind, with ssh-keygen's own words. `loxodonta verify-package` judges the seal through `ssh-keygen -Y verify` under the shipped key and on success prints `seal signature: SIGNED (key: SHA256:<fingerprint>)` and adds `+ SIGNED (key: ...)` to the verdict line, after `+ ANCHORED` when both hold: the fingerprint and never a name or the key's comment, for the recipient to compare against a channel the package cannot rewrite. A signature that does not hold, or a shipped key that is not the one that signed, is `SEAL-INVALID`; a declared signature with no `.sig` or no `.pub` is `SEAL-MISSING`; both exit 3. A recipient whose ssh-keygen is missing, cannot run, or predates `-Y verify` is told the signature was not judged, and the ladder reports the rungs it could judge. The residual-trust line names what each seal gives, when and which key, and what still rests on the issuer's word. `docs/PACKAGE.md` carries the custody cage: a key any process of this user could use without the operator, unencrypted in `~/.ssh` or loaded in `ssh-agent`, is writer-reachable and its signature is testimony; a FIDO2 key that needs a touch, or signing on another machine, is out of reach.
- `install-hook --publish-head URL` (ADR-0025): opt in once, and every session end publishes the chain head to a remote the credentials on this machine cannot delete from (a chat incoming webhook, a retention-locked bucket), after the tail commitment and before the anchor, quietly and best-effort inside the same session-end budget. `hook --publish URL` carries it; a re-run of the installer without the flag turns it off; `uninstall-hook` removes it. What leaves is `head`, `n`, `session`, `ts`, `event`, and one readable line under both `text` and `content`; never a path, a project name, an action line, or chain bytes. Codex takes the flag as well, with the POST cut off at half its three-second SessionEnd cap (#183). The installer refuses anything but a plain http or https URL with nothing a shell could act on, since the wired command runs through a shell; the three-second cap covers name lookup; a redirect is a failure.
- `install-hook --codex --publish-head URL` (ADR-0025 ruling 3, #183): the published head is wired for Codex, whose SessionEnd hook is capped at three seconds. Measured before wiring, on the author's one machine, and the numbers are in `docs/HOOK.md`: sealing a 2 MB transcript costs 0.20s, the POST 0.06s over it, and a real webhook's handshake under a tenth of a second, while an unreachable remote that silently drops the request cost the full three-second wait and landed past the cap. So a Codex hook waits 1.5 seconds for its POST instead of three, half the cap, which left the worst failure path near 1.8s, and what it cuts off the keeper publishes later. The seal is not bounded, so a very large transcript narrows that margin: `docs/HOOK.md` carries the sizes. The session-end anchor stays refused for Codex: that is a calendar round trip, not one POST.
- `supervisor scan|serve --publish-every AGE --publish-url URL` (ADR-0025 ruling 3, #182): the keeper's half of the published head, for machines that run around the clock and for sessions that never reached their end. On each tick, a chain whose head has aged past the cadence and has not left yet is published once through the new `loxodonta publish --log LOG URL`, the same body as the session-end publish with `event` set to `cadence`, on the anchor keeper's throttle. What was published is remembered in `<log>.published.jsonl` beside the chain (`head`, `n`, `ts`, `event`; never the URL), writer-reachable and therefore testimony: it stops a repeat and proves nothing. The scan report gains `left` per chain, when a head last left the machine and by which door (`published` or `anchored`), and the dashboard paints it as staleness beside the anchor age, never as an alarm and never in the exit code. The two flags go together or the command is refused (exit 64); off by default, nothing leaves the machine without them. `loxodonta publish` refuses anything but a plain http or https URL (exit 64), refuses redirects, names a failure on stderr without echoing the URL, and writes no memo for a POST that did not land. The session-end hook leaves the same memo, so the keeper never repeats a head the hook sent; `adopt` moves the memo with the chain; an anchored head's departure is its first record, not its proof's upgrade.

### Changed

- The field-data export's `--raw` zip is a *raw archive* (ADR-0026 ruling 9): the prompt, the issue template, and the help text say so; *package* is reserved for the sealed deliverable above.
- Usage errors exit `64` (sysexits `EX_USAGE`) in both `loxodonta.py` and `supervisor.py`: an unknown flag, a missing required argument, or a malformed value (`--expect-head`, `--anchor-every`) no longer shares exit `2` with `FILES-DIVERGED`, so a verdict exit is never an argparse error. Argparse's message on stderr is unchanged, and every verdict exit is untouched: the recorder's `0` to `5`, and `scan`'s `0` to `7` (ADR-0026 ruling 7, #175).

## [0.2.0] - 2026-09-08

The release after the measurement: what the orientation-cost run (EXPERIMENTS §6) found is fixed or stated, the window between anchors is closed for anyone who opts in at install, and the front door says how the repo is built.

### Changed

- The coverage claim states its edge: what the harness does on a session's behalf outside any tool call (a worktree it merges when a session leaves it) fires no hook and leaves no receipt; HOOK.md, the GLOSSARY, and the README's defends-against table say so, and point at git's reflog for the pointer move (#156).
- One session, one drawer (ADR-0023): every receipt of a session goes to the drawer its first receipt chose, so a project directory that resolves differently mid-session can no longer split a session's chain in two. Store-routed writes only; `--log-dir` and the cwd-local default are untouched.
- The digest header says what it leaves out: when a chain holds bookkeeping entries (transcript commitments), the header adds `plus N bookkeeping entries not rendered (last n M)`, so a row's sequence number never reads as a missing receipt (#154).

### Added

- `install-hook --anchor-at-session-end` (ADR-0024): opt in once, and every session end anchors the chain head to Bitcoin through OpenTimestamps, after the tail commitment, quietly and best-effort under a fixed budget, then spends the leftover budget upgrading the drawer's pending proofs. `hook --anchor` and `hook --calendar` carry it. Nothing leaves the machine without the opt-in; the `gh` head ledger is rejected as writer-reachable.
- `supervisor verify ADDRESS`: the recorder's verdict on the chain holding an entry address, printed verbatim with its exit code, the CLI twin of the MCP tool (ADR-0019, one-to-one restored). `show` names the chain's full path and the verify command; the digest footer names it too, so an agent holding an address never has to hunt for the chain file (#155).
- A repository's recall (`digest`, `search`, `timeline`) also reads the drawers of its own harness worktrees (`<repo>/.claude/worktrees/`), so a session split before this release is shown whole.

### Fixed

- A worktree the harness deregistered under a running session still logs to its repository's drawer: the `.git` file names the repository even after `<main>/.git/worktrees/<name>` is gone.
- A long action line is cut between words, never inside one, and never between a letter and its accent or inside an emoji sequence; a run with no space near the limit is still cut at the limit (#157).
